# 第二個 PR 建議範圍

第一個任務只加入結構檢查與瀏覽器回歸測試。遊戲資料、數值、規則、AI、UI 文案及 legacy 均維持原樣。

## 分離 game.js 的步驟

1. `state.js`：先移出 `newPlayer` 與 `game` 初始狀態；保留每次開始時重新建立狀態的行為，以及物件參照、初始化時機。
2. `rules.js`：移出骰子、資源、疲勞、議題倍率、行動、格子效果、移動、結算公式。保持呼叫順序與亂數消耗次數。先使用明確的 render/log 回呼連接 UI，避免一次改寫規則。
3. `ai.js`：移出 `chooseAiBranch`、`aiChooseAction`、`aiTurn`。保留原有排序比較器、權重及亂數行為；下一個 PR 不重寫評分方式。
4. `ui.js`：移出 render 函式、候選人選擇、路線 modal、結果 modal 與紀錄。移動邏輯呼叫路線選擇回呼，UI 回傳所選路線。
5. `game.js`：保留開始遊戲、玩家回合與 AI 回合的流程協調，以及 DOM 綁定與啟動入口。依資料 → 棋盤 → state → rules → ai → ui → game 載入，不混用 classic script 與 ES module。

每一步獨立提交，執行固定種子的 legacy 對照測試；維持桌面與手機的操作檢查。由於拆分後函式位置與依賴會改變，屆時調整測試的來源檢查範圍，繼續保留資料與狀態軌跡比對，不修改 legacy。

## 驗收與後續

- 六名候選人、五名 AI、48 節點、五個 gate、12 種行動保持一致。
- 同一種子與同一操作序列的每次移動、AP 行動、AI 回合、議題、最後一輪及最終結果一致。
- 規則層能在不建立 DOM 的情況下被呼叫；以注入 RNG 與事件回呼作為後續 simulation harness 的入口，預設仍使用原本 Math.random 行為。
- 模擬工具、AI 權重集中化、棋盤視覺重做、規則修正與平衡分析另開後續 PR，避免混入此次重構。

目前沒有提供 Git remote 或 GitHub repository；本次交付可供建立第一個 PR 的本機專案，不包含遠端發布。
